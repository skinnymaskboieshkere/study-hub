## 2. Не делаем и юридические ограничения

- **Не скачиваем видео с YouTube** (никакого yt-dlp для медиа). Воспроизведение — только через официальный **YouTube IFrame Player API**. «База видео» — это каталог: ID, названия, длительность, порядок, пререквизиты. Сами видео стримятся во встроенном плеере.
- Не скрываем брендинг YouTube и не блокируем рекламу в плеере.
- Используем только **бесплатные официальные** источники: каналы и сайты самих университетов или преподавателей (CS50, MIT OpenCourseWare, Stanford Online, Open Yale Courses, Columbia FPCV, Michigan Online, Northwestern). Перезаливы с чужих каналов не берём.
- Для каждого курса храним и показываем лицензию и ссылку на источник. Многие из них распространяются по CC BY-NC-SA: только некоммерческое использование, с указанием автора.
- **Реверс-инжиниринг чужих приложений не делаем.** Uolia Learning используем только как визуальный референс (скриншоты и описание). Её код и ресурсы не декомпилируем и не копируем, логотипы и иконки не переносим. Дизайн делаем своим, «по мотивам».
- Офлайн-видео — только в бэклоге и только для файлов, которые источник сам раздаёт для скачивания под открытой лицензией.
- Нет аккаунтов, облачной синхронизации, мобильного приложения и ИИ-функций в MVP (см. бэклог).

## 3. Архитектура и стек (решения по умолчанию)

**Тип:** локальное веб-приложение на `http://127.0.0.1:5180` плюс PWA (устанавливается с иконкой).

> Почему не Electron/Tauri: YouTube-эмбедам нужен корректный HTTP `Referer`. В обёртках с нестандартной схемой (`tauri://`, `file://`) плеер часто падает с **Error 153**. На `http://localhost` такой проблемы нет.

| Слой | Выбор |
|---|---|
| Язык | TypeScript (`strict: true`) |
| Фронтенд | React + Vite, React Router, TanStack Query, Zustand |
| UI | Tailwind CSS + shadcn/ui (Radix), lucide-react, Framer Motion (аккуратно, для микроанимаций) |
| Бэкенд | Node.js + Fastify (или Hono), REST под `/api` |
| БД | SQLite: better-sqlite3 + Drizzle ORM (миграции), FTS5 для поиска |
| Заметки | **Обычные `.md`-файлы в папке vault.** SQLite хранит только индекс. Хранилище должно открываться в настоящем Obsidian без потерь |
| Редактор | CodeMirror 6 + свои расширения |
| Рендер markdown | unified: remark-gfm, remark-math + rehype-katex, подсветка кода (Shiki), свой плагин для `[[wikilinks]]` и `![[embeds]]` |
| Граф и дорожная карта | react-force-graph-2d (граф заметок); React Flow / @xyflow/react (дорожная карта курсов) |
| Отслеживание файлов | chokidar |
| Тесты | Vitest (unit), Playwright (e2e главных сценариев) |
| Качество | ESLint + Prettier, скрипты `typecheck`, `lint`, `test` |
| CI | GitHub Actions: typecheck + lint + test на каждый push |

**Структура репозитория (ориентир):**

```
study-hub/
  SPEC.md  CLAUDE.md  PROGRESS.md  README.md  LICENSE
  docs/BRIEF.md  docs/ASSESSMENT.md  docs/design/reference/*.png
  .github/workflows/ci.yml
  .env.example            # YOUTUBE_API_KEY=, VAULT_PATH=, PORT=5180
  data/                   # study.db — НЕ в git
  vault/                  # заметки — НЕ в git по умолчанию (см. 3.1)
  seed/courses/*.json     # каталог курсов (в git)
  seed/tracks.json        # треки, порядок и пререквизиты (в git)
  scripts/import-playlist.ts
  src/server/ src/client/ src/shared/
```

- `npm run dev` поднимает сервер и Vite вместе. `npm run build && npm start` запускает один процесс на `127.0.0.1:5180`.
- Сервер слушает только `127.0.0.1`. Пути к заметкам проверяются: файл должен лежать внутри vault (защита от path traversal).
- `Referrer-Policy: strict-origin-when-cross-origin`. Если есть CSP, `frame-src` разрешает `https://www.youtube.com` и `https://www.youtube-nocookie.com`.

## 5. Модель данных (SQLite)

- `tracks` (id, slug, title, color, sort_order, description)
- `courses` (id, slug UNIQUE, title, university, instructors_json, subject, level, track_id, sort_order, source_url, license, description, status `candidate|imported`, **collection** `wishlist|active|completed|archived`, verified_at)
- `course_prerequisites` (course_id, requires_course_id, min_progress)
- `units` (id, course_id, title, sort_order)
- `videos` (id, course_id, unit_id, youtube_id UNIQUE, title, duration_sec, kind, sort_order, note_path NULL)
- `video_progress` (video_id PK, position_sec, max_position_sec, completed_at NULL, updated_at)
- `bookmarks` (id, video_id, t_sec, label, created_at) — быстрые закладки внутри видео, без конспекта
- `study_plans` (id, name, start_date, study_weekdays_json, active, created_at)
- `plan_courses` (plan_id, course_id, minutes_per_day, include_kinds_json, priority)
- `plan_items` (id, plan_id, date, video_id, start_sec, end_sec, status `planned|done|skipped`, sort_order)
- `tasks` (id, date NULL, title, done, created_at, done_at)
- `study_sessions` (id, date, course_id, seconds) — фактическое время просмотра для статистики
- `settings` (key PK, value_json)
- Индекс заметок: `notes` (path PK, title, mtime, frontmatter_json), `note_links` (src_path, target_path NULL, raw_target, kind `wikilink|embed|video`, video_id NULL, t_sec NULL), `note_tags` (path, tag), `notes_fts` (FTS5).

Источник правды для заметок — **файлы**. Индекс пересобирается при старте (инкрементально по `mtime`) и обновляется по событиям chokidar.

## 6. Функциональность и критерии приёмки

### 6.1 Каталог курсов (в духе Uolia)
- **Каталог**: сетка карточек с обложкой (превью первой лекции с `i.ytimg.com`), университетом, преподавателем, уровнем, кольцом прогресса и бейджем трека. Сверху фильтры-«чипсы»: трек, предмет, университет, уровень.
- **Коллекции** как в Uolia: «Хочу пройти», «В процессе», «Завершено», «Архив». Курс переносится между ними в один клик, а «В процессе» включается автоматически при первом просмотре.
- **Страница курса**: шапка (описание, лицензия, ссылка на источник, пререквизиты и их выполнение), список модулей и видео (просмотрено/частично/нет, длительность, есть ли конспект), материалы. Для курса-кандидата — кнопка «Импортировать видео».

### 6.2 Плеер и экран «Учёба»
- YouTube IFrame Player API, `youtube-nocookie` включается в настройках.
- Позиция сохраняется каждые ~5 с, при паузе и при закрытии; при повторном открытии видео продолжается с того же места.
- Видео отмечается просмотренным, когда `max_position_sec ≥ 90%` длительности; можно отметить и вручную.
- Скорость воспроизведения и горячие клавиши: пробел, ←/→ ±10 с, `Shift+←/→` для скорости, `B` — закладка. Хоткеи не перехватываются, пока фокус в редакторе, кроме хоткея таймкода (6.6).
- **Закладки**: список в боковой панели, клик перематывает видео; закладку можно превратить в таймкод в конспекте.
- **Фокус-режим**: без бокового меню и лишнего UI, только видео и заметка.
- **Раскладка «Учёба»**: видео плюс заметка к лекции, разделитель можно перетаскивать. Справа выдвигается плейлист курса с «следующим видео».
- Если плеер вернул ошибку (101/150/153), показывается понятное сообщение и кнопка «Открыть на YouTube».

**Приёмка:** посмотрел 3 минуты → закрыл вкладку → открыл снова → видео продолжилось с ~3:00, прогресс курса изменился, курс сам переехал в «В процессе».

### 6.3 Дорожная карта (Roadmap) — «дерево навыков»
- Отдельная страница с графом курсов (React Flow): 4 колонки или слоя треков, стрелки пререквизитов.
- У узла есть состояния: **доступен**, **рекомендуется подождать** (пререквизит ниже `minProgress`), **в процессе**, **завершён**. Каждое состояние видно по цвету, кольцу прогресса и иконке. Цель «Computer Vision» визуально выделена в конце пути.
- Наведение на узел показывает, чего не хватает: «Рекомендуется сначала пройти 18.06 — сейчас 40% из 60%».
- Клик по узлу открывает курс. Кнопка «Добавить в план» тоже есть на узле.
- Сверху сводка: «До трека Computer Vision осталось ~N часов по рекомендованному пути».

**Приёмка:** пройдя 60% 18.06, вижу, что EECS 498 на карте стал «доступен», а оценка «осталось часов» уменьшилась.

### 6.4 План обучения и экран «Сегодня»
- **Мастер плана**: курсы (по умолчанию — активные из трека 1), дата старта, учебные дни недели, минуты в день на курс (по умолчанию 45–60, уточнить на интервью). Можно учесть мои пары и сессию: дни с меньшей нагрузкой или «дни без учёбы».
- **Планировщик** — чистая функция `buildSchedule(input) → PlanItem[]` с unit-тестами:
  - идёт по непросмотренным видео курсов по порядку и раскладывает их по учебным дням в пределах бюджета;
  - **режет длинные видео на части** (`start_sec`/`end_sec`), каждая часть не короче 10 минут;
  - уважает приоритеты курсов и не планирует уже просмотренное.
- **Перепланирование**: невыполненные пункты прошедших дней переносятся вперёд и сдвигают остальной план. Плюс кнопка «Перепланировать».
- **Экран «Сегодня»** (главный): видео и части на сегодня (клик открывает «Учёбу» на нужном отрезке, по концу отрезка — «Часть выполнена»), мои задачи (добавить, отметить, перенести), прогресс дня, серия дней подряд (streak), ссылка на дневную заметку, мини-виджет «прогресс к CV».
- **Календарь** неделя/месяц с цветом по предмету.

**Приёмка:** план «3 курса по 60 мин, пн–пт» → на «Сегодня» ~180 мин → пропускаю день → невыполненное переехало, остальной план сдвинулся.

### 6.5 Заметки в стиле Obsidian
- Vault на диске (`VAULT_PATH`), `.md` + YAML frontmatter, вложения в `attachments/`.
- Дерево файлов: создание, переименование, перемещение, удаление в `.trash/`.
- Редактор CodeMirror 6: режимы «редактирование / просмотр / split», автодополнение `[[`, `[[Заметка|алиас]]`, `[[Заметка#Заголовок]]`, `![[встраивание]]`, `#теги` (включая вложенные), **формулы KaTeX** (`$…$`, `$$…$$`), подсветка кода (C, Python, SQL, JS, MATLAB), вставка картинок из буфера, автосохранение.
- Обратные ссылки с контекстом; **переименование обновляет ссылки** во всём хранилище.

- Панель тегов, дневные заметки `Daily/YYYY-MM-DD.md`, шаблоны в `Templates/`.

### 6.6 Связка «видео ↔ заметки»
- Кнопка «Конспект» создаёт заметку `Courses/<Курс>/<NN> - <Лекция>.md` из шаблона: frontmatter (`type: lecture`, `course`, `video`, `url`, `status`, `tags`), разделы «Главные идеи», «Таймкоды», «Формулы», «Непонятно», «Связи», «Где пригодится (робототехника / CV)».

## 9. Подводные камни

### 9.1 YouTube
- IFrame API загружается один раз (singleton-промис). Плеер создаётся на `div` и уничтожается при размонтировании.
- Error 153 — нет Referer: проверь `Referrer-Policy` и не ставь `referrerpolicy="no-referrer"`. Ошибки 101/150 — автор запретил встраивание: показывай кнопку «Открыть на YouTube».
- Позицию сохраняй с debounce и в `visibilitychange`/`pagehide` (`navigator.sendBeacon`).
- Конец отрезка отслеживай своим таймером: на параметр `end` не полагайся.

### 9.2 Импорт
- `scripts/import-playlist.ts <playlistUrl|id> --course <slug>`. Если есть `YOUTUBE_API_KEY`: `playlistItems.list` (50 на страницу, 1 единица квоты) + `videos.list` пачками по 50 для длительности (ISO-8601 → секунды). Квоты по умолчанию (10 000 единиц в сутки) хватает с запасом. **Не используй `search.list`** (100 единиц).
- Без ключа ID берутся со страниц OCW или курса, а длительность подставляет плеер через `getDuration()`.
- Отбрасывай дубли, трейлеры, приватные и удалённые видео.

### 9.3 Заметки
- Имена файлов на кириллице с пробелами. Ссылки разрешаются по имени без `.md`, без учёта регистра, как в Obsidian.
- Не реагируй на свои же записи в событиях chokidar (сравнивай по хешу или mtime).
- Переименование: атомарный rename → обновление ссылок → переиндексация, плюс отчёт «изменено N ссылок».
- Не трогай чужие поля frontmatter.

### 9.4 Прочее
- Даты храни как `YYYY-MM-DD` (локальные), время — в UTC ISO. Неделя начинается с понедельника, часовой пояс берётся из системы (у меня Europe/Kyiv).
- better-sqlite3 на Windows: если не ставится, опиши решение в README. Запасной вариант — `node:sqlite`, если он стабилен в текущем LTS.
- Никаких секретов в git. Перед каждым push проверяй `git status` и diff на наличие `.env`, `data/` и `vault/`.
