# Study Hub — ASSESSMENT (самооценка Claude Code)

> Дата: 2026-11-18. Основа: `SPEC.md` (раздел 13) и подтверждённый `docs/BRIEF.md`.

## 1. Сложность

**Общая оценка: 7/10.** Сложных алгоритмов здесь мало. Сложность в объёме работы и в заметках уровня Obsidian, которые работают с настоящими файлами.

| Компонент | Оценка | Почему |
|---|---|---|
| Каталог и плеер | 4/10 | IFrame API хорошо известен. Трудности: фокус клавиатуры внутри видео YouTube и русские субтитры (см. риски). |
| Планировщик | 5/10 | Чистая функция, но правил много: общий бюджет дня, чередование 1–2 предметов, приоритеты, нарезка видео на части ≥ 10 мин, практика, срок для CS50P (февраль), перенос пропущенного. Хорошо покрывается тестами. |

### Главные риски

1. **Целостность заметок — самый большой риск.** Переименование правит ссылки во многих файлах сразу. OneDrive может держать файлы «только в облаке», создавать конфликтные копии и сам переписывать файлы во время синхронизации. Ошибка здесь — испорченные конспекты.
   Как снижаю: тесты на копии хранилища, атомарная запись файлов, отчёт «изменено N ссылок», бэкап перед массовыми операциями, удаление только в `.trash/`.
2. **Ручная проверка курсов.** Каждый курс нужно открыть на официальной странице, найти плейлисты, отделить практику от лекций. Это время, а не код.
   Как снижаю: YouTube API-ключ, импортёр, проверка по одному треку за раз.
3. **Плеер.**
   - Когда кликаешь по видео, фокус уходит внутрь окна YouTube, и горячие клавиши приложения перестают работать. Нужен механизм возврата фокуса.
   - Официально API позволяет только задать язык субтитров. Автоперевод на русский может не включиться программно — тогда в плеере будет подсказка, как включить его в два клика.
4. **Объём проекта.** 8 этапов, легко увязнуть в полировке.
   Как снижаю: строгая приёмка по критериям этапа, всё лишнее — в бэклог.

## 3. Что бы я изменил в SPEC

1. **Разделить этап 1** на 1a (витрина `/dev/ui` и каркас с верхним меню — утверждаешь ты) и 1b (курсы трека 1, каталог, плеер). Сейчас этап слишком большой, а утвердить дизайн до массовой вёрстки SPEC и так требует.
2. **Оценка часов для курсов-кандидатов.** Добавить в seed поле `estimatedHours` уже на этапе 1. Иначе «прогресс к CV» (этап 2) и «осталось часов до CV» (этап 6) не из чего считать: полный импорт треков 2–4 только на этапе 7.
3. **Логику дорожной карты — раньше.** Функцию `computeRoadmapState` сделать на этапе 2 для мини-виджета «прогресс к CV» на «Сегодня». Сам граф React Flow оставить на этапе 6.
4. **YouTube API-ключ — обязательно до этапа 1.** Без него у видео нет длительностей, и планировщику не из чего строить план: `getDuration()` отдаёт длительность только после открытия видео.
5. **Модель данных под BRIEF:**
   - Одно видео может входить в несколько курсов: ступень 4 трека CV переиспользует лекции 6.4210 и CS231n, а практику из «SC»-версии курса можно добавить к лекциям другой версии. Сейчас `videos.youtube_id UNIQUE` и один `course_id` этого не позволяют. Решение — таблица-связка `course_videos (course_id, video_id, unit_id, sort_order)`, прогресс общий на видео.
   - Общий бюджет дня и чередование: `study_plans.minutes_per_day` плюс `plan_courses.weight` (доля недели) и `plan_courses.deadline` (например, CS50P к февралю) вместо минут на каждый курс.
   - В план по умолчанию: `lecture`, `recitation`, `section`, `problem-solving`.
6. **Восстановление из бэкапа** — не поверх vault, а сначала в отдельную папку и с подтверждением. Учесть, что бэкап vault из OneDrive скачает файлы, которые лежат «только в облаке».

### Противоречия внутри SPEC

- Хоткей таймкода `Ctrl+Shift+T` занят браузером (решено в BRIEF).
- Мини-виджет «прогресс к CV» стоит на этапе 2, а логика дорожной карты — на этапе 6 (п. 3).
- «Осталось часов до CV» требует длительностей курсов, которые импортируются только на этапе 7 (п. 2).
- `youtube_id UNIQUE` не даёт переиспользовать лекции в ступени 4 трека CV (п. 5).
- Хоткеи «пробел, ←/→» (6.2) не работают, пока фокус внутри видео YouTube (риск 3).
- Боковое меню (раздел 7) и настройка темы (6.8) — решено в BRIEF: меню сверху, только тёмная тема.

### Не плагин, но обязательно до этапа 1: YouTube Data API-ключ

1. Открой console.cloud.google.com и создай проект (например, `study-hub`).
2. **APIs & Services → Library** → найди **YouTube Data API v3** → **Enable**.
3. **Credentials → Create credentials → API key**. В настройках ключа ограничь его только YouTube Data API v3.
4. Вставь ключ в файл `.env` (создам его на этапе 0) в строку `YOUTUBE_API_KEY=`. **В чат ключ не присылай.**

Это бесплатно: дневной квоты (10 000 единиц) хватает с большим запасом.

## 5. Реверс-инжиниринг

**Не нужен — подтверждаю.** Всё берём через официальные интерфейсы: YouTube IFrame Player API, YouTube Data API v3 и открытые страницы курсов. Uolia — только настроение, главный референс теперь твой макет. Разбирать чужое приложение запрещает раздел 2 SPEC, и это, скорее всего, нарушило бы его лицензию.

Полезнее вместо него:
- разбор твоего макета (я вижу изображения) → дизайн-токены: цвета, скругления, свечение;
- frontend-design → качество интерфейса;
- accessibility-review из Design → контраст по WCAG AA;
- скриншоты встроенного браузера → сравнение результата с макетом на каждом этапе.
