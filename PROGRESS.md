## Этап 6 — дорожная карта (19.11.2026)

**Сделано**

- **Страница «Траектории»** (`/roadmap`): карта курсов на React Flow. Четыре трека идут колонками,
  стрелки ведут от пререквизитов. В конце пути выделена цель «Computer Vision» с оставшимися часами.
- **Состояния узла**: «Можно начинать» (светится), «Лучше подождать» (пунктир, песочные часы),
  «В процессе» (кольцо с процентом), «Пройден» (зелёная галочка). Стрелка сплошная, если
  пререквизит пройден, пунктирная, если ещё нет, и точечная для «желательно».
- **Наведение** на курс подсвечивает его стрелки и показывает, чего не хватает: «Рекомендуется
  сначала пройти 18.06 — сейчас 40% из 60%».
- **Клик** по карточке открывает курс. Значок календаря открывает мастер плана, где курс уже отмечен
  (`/plan?add=<курс>`). На курсах без видео вместо него значок «видео ещё не импортированы».
- **Сводка сверху**: «До трека Computer Vision осталось ~N часов по рекомендованному пути».
- **Вид «Списком»**: те же карточки по трекам, удобнее на телефоне.
- **«Желательные» пререквизиты** (SPEC §4: «Stat 110 (желательно)»). Они видны в подсказке и на
  странице курса, но не переводят курс в «Лучше подождать».
- `npm run catalog -- --tracks` пересобирает только `seed/tracks.json`, без запросов к YouTube.
- 16 новых модульных тестов: состояния, раскладка, подсказки, API. 2 новых сквозных теста: приёмка
  §6.3 и «Добавить в план».

**Как проверить**

```bash
npm run dev
```

1. Открой «Траектории». Наведи курсор на EECS 498: появится подсказка, чего не хватает.
2. Посмотри 18.06 до 60% (или отметь лекции просмотренными). Если CS50P и 18.01 уже пройдены на
   80%, EECS 498 станет «Можно начинать», а часов до CV станет меньше.

Сквозные тесты: `npm run test:e2e`.

**Приёмка 6.3** — проверено сквозным тестом и вручную на тестовой базе (порт 5190):

- до порога, при 41% по 18.06: EECS 498 «Лучше подождать», в подсказке «18.06 — сейчас 41% из
  60%», до CV ~31 час;
- после порога, при 62% по 18.06: EECS 498 «Можно начинать», до CV ~25 часов.

**Решения**

- Stat 110 стал «желательным» пререквизитом EECS 498 и CS231n, как в SPEC. Он пока кандидат без
  видео. Будь он обязательным, оба курса CV никогда не открылись бы. В часы до CV он входит:
  рекомендованный путь его включает.
- React Flow 12.12, а не 13.0: тринадцатая вышла три дня назад и пока сырая.
- Курс, который уже начат, остаётся «В процессе», даже если пререквизиты не пройдены (они мягкие).
  Подсказка всё равно называет, чего не хватает.
- Курс считается пройденным с 99% (титры в конце не важны) или когда его отметили «Пройдено».
- Карта открывается в читаемом масштабе: по ширине, но не мельче 60%. Колесо мыши прокручивает
  карту, Ctrl + колесо масштабирует. Страница и React Flow грузятся только при открытии
  «Траекторий», поэтому главный бандл не вырос.

## Этап 5 — граф и Obsidian-полировка (19.11.2026)

**Сделано**

- **Переименование и перенос заметок** с правкой ссылок по всему хранилищу: `[[ссылки]]`,
  `[[…#заголовок|алиас]]` и встраивания `![[…]]` указывают на новое имя, код не трогается. После —
  отчёт «Обновлено N ссылок в M заметках». Кнопка в панели заметки и команда в палитре.
- **Граф заметок** `/notes/graph`: цвет по трекам (конспекты лекций — цветом своего трека) или по
  тегам; фильтры по названию и тегу, «несозданные» и «без связей». Наведение подсвечивает соседей,
  клик открывает заметку (несозданную — создаёт). **Локальный граф** — в правой панели заметки.
- **Встраивания**: `![[Заметка]]` и `![[Заметка#Заголовок]]` показывают другую заметку или её раздел
  прямо внутри; `![[картинка.png|300]]` — картинку (число — ширина).
- **Картинки**: вставка из буфера обмена или перетаскиванием в редактор → файл
  `attachments/Pasted image ГГГГММДДЧЧММСС.png`, в тексте — `![[…]]`, как в Obsidian.
- **Палитра команд** Ctrl+P: новая заметка, дневная, переход, поиск, граф, корзина, переименование,
  режимы, вставка шаблонов.
- **Корзина**: список удалённых заметок из `.trash`, «Вернуть» и «Удалить навсегда» (с подтверждением).
- **Сквозные тесты (Playwright)**, 5 штук: полная приёмка 6.5, встраивание, Ctrl+O и Ctrl+P,
  корзина, мастер плана → «Сегодня». Идут на копии тестового хранилища и в CI на GitHub.
- 224 модульных теста (после этапа 4 было 206) + 5 сквозных.

**Как проверить**

```bash
npm run dev
```

В «Заметках»: поставь в заметке ссылку `[[…]]` на другую, переименуй ту (кнопка с курсором в
панели) — ссылка поменяется сама. Граф — кнопка в левой колонке или Ctrl+P → «Граф». Сквозные
тесты: `npm run test:e2e` (используют установленный Chrome).

**Приёмка 6.5 целиком (сквозной тест + проверка во встроенном браузере на тестовом хранилище)**

- Ссылка через автодополнение `[[Произв` → обратная ссылка у «Производной» → переименование в
  «Производная функции» → в «Пределах» стало `[[Производная функции]]`, «Обновлено 1 ссылка в 1
  заметке» → обе заметки связаны на графе → формула отрисована KaTeX.
- Встраивание раздела `![[Пределы#Замечательные пределы]]` показывает раздел с формулой; локальный
  граф рисует связи открытой заметки; на ширине телефона страницы не уезжают вбок.

**Решения**

- Переименование сначала переносит файл, потом правит ссылки и переиндексирует — порядок из SPEC
  §9.3. Ссылка, текст которой не меняется (перенос в другую папку), файл не трогает.
- Запоздавшее автосохранение заметки, которую уже переименовали или удалили, сервер отклоняет —
  иначе оно бы «воскресило» файл под старым именем. Это проверяется тестом.
- Вставленные картинки отдаются только как картинки, а SVG — с запретом скриптов.
- Сквозные тесты локально идут в твоём Chrome, чтобы не скачивать отдельный браузер; CI скачивает
  Chromium сам.
- Сквозные тесты нашли две вещи: CodeMirror специально не принимает Enter первые ~75 мс после
  появления подсказок (защита от случайного выбора — человеку это не мешает), и горячие клавиши
  заметок работают только после загрузки экрана. Тесты ждут, как ждал бы человек.

**Известное**

- Переименование папок целиком (с правкой ссылок) пока нет — только заметок; папку можно
  переименовать в Obsidian, приложение подхватит изменения.
- Ссылки в стиле Markdown `[текст](Заметка.md)` при переименовании не правятся — только `[[…]]`
  (в Obsidian по умолчанию используются они).

## Этап 4 — видео ↔ заметки (18.11.2026)

**Сделано**

- Кнопка «Конспект» под видео: открывает рядом с плеером конспект лекции, а если его ещё нет —
  создаёт `Courses/<курс>/<NN> - <лекция>.md` из шаблона: свойства (`type: lecture`, `course`,
  `video`, `url`, `status`, `tags`) и разделы «Главные идеи», «Таймкоды», «Формулы», «Непонятно»,
  «Связи», «Где пригодится (робототехника / CV)». Свой шаблон — `Templates/Лекция.md` в vault.
- Раскладка «Учёба»: видео | конспект, границу можно перетаскивать (и двигать стрелками с
  клавиатуры). Плейлист курса при открытом конспекте выдвигается справа кнопкой «Программа».
- **Alt+T** вставляет таймкод `[▶ 12:34](https://www.youtube.com/watch?v=…&t=754s)` — обычную
  ссылку YouTube, которая работает и в Obsidian. Работает и из редактора, и когда фокус на видео.
- Клик по таймкоду (или Ctrl+клик в редакторе): та же лекция — перемотка; другая — она открывается
  на нужной секунде (`/watch/…?t=754`). Ссылки на YouTube в любых заметках попадают в индекс.
- У лекции вкладка «Заметки»: все заметки, которые на неё ссылаются, с таймкодами — клик
  перематывает видео. В программе курса у лекций с конспектом есть значок.
- Дневная заметка `Daily/ГГГГ-ММ-ДД.md` с планом дня в виде чек-листа: кнопка на «Сегодня» и в
  заметках. Свой шаблон — `Templates/Дневная заметка.md`.
- «Вставить шаблон» в заметках: любой файл из `Templates/`, подставляются `{{date}}`, `{{time}}`,
  `{{title}}` (как в Obsidian).
- 202 теста (после этапа 3 было 184): ссылки YouTube и таймкоды, шаблоны, имена файлов, API
  конспектов, дневных заметок и заметок к видео, поиск ссылки под курсором в редакторе.

**Как проверить**

```bash
npm run dev
```

1. Открой любую лекцию → «Конспект» → «Создать конспект»: справа появится заметка из шаблона.
2. Поставь курсор под «Таймкоды» и нажми Alt+T — вставится таймкод текущего момента.
3. Закрой видео, открой эту заметку в «Заметках», переключись на «Просмотр» и кликни таймкод —
   откроется та же лекция на той же секунде.
4. На «Сегодня» — «Дневная заметка».

**Приёмка (проверено во встроенном браузере, на тестовом хранилище и отдельной базе)**

- 18.01, лекция 1: «Конспект» → создан `Courses/18.01/01 - Лекция 1 — Rate of Change.md` со всеми
  разделами. Видео на 12:34 → Alt+T → в файле `[▶ 12:34](…&t=754s)`.
- Видео закрыто → заметка в «Заметках» → клик по ▶ 12:34 → открылась та же лекция, плеер на 12:34 и
  играет. Во вкладке «Заметки» у лекции — конспект с таймкодом; клик перематывает на 12:34.
- Дневная заметка создана с двумя частями плана; шаблон «Задача» вставился с датой и временем.
- Ширина телефона — без горизонтальной прокрутки; на широком экране видео и конспект рядом.

**Решения**

- Хоткей таймкода — Alt+T, а не Ctrl+Shift+T из SPEC: это сочетание браузер забирает себе (BRIEF).
  Сменить его можно будет в настройках на этапе 7.
- Конспект находится по полю `video:` в свойствах заметки, а не по имени файла: заметку можно
  переименовать или перенести — связь с лекцией не потеряется.
- Если твой шаблон лекции без поля `video:`, приложение добавит его само — иначе каждый клик
  «Конспект» создавал бы новую заметку.
- Индекс заметок пересобирается один раз после обновления (это только кэш), чтобы найти ссылки на
  YouTube в уже существующих заметках.
- Проверки теперь идут на отдельном сервере (порт 5190) со своей базой `data/sandbox` и тестовым
  хранилищем: во время проверки у тебя был запущен `npm run dev`, и я его не трогал.
- Редактор в «Учёбе» загружается только при открытии конспекта — экран видео не стал тяжелее.
- Если нажать Alt+T, не ставя курсор в заметку, таймкод уходит в конец раздела «Таймкоды»
  (или в конец заметки), а не в начало файла: на проверке он сначала попал перед свойствами YAML
  и сломал бы их — исправлено и закрыто тестом.

**Известное**

- Встраивания `![[…]]`, картинки, граф и переименование с правкой ссылок — этап 5.

## Этап 3 — заметки: ядро (18.11.2026)

**Сделано**

- Хранилище: твой Obsidian vault из `VAULT_PATH`. Заметки остаются обычными `.md`-файлами, база
  хранит только индекс: при старте он догоняет файлы по времени изменения, дальше следит за папкой
  (правки в Obsidian и через OneDrive видны в приложении через пару секунд).
- Экран «Заметки» в три колонки: дерево файлов | заметка | обратные ссылки, теги, оглавление.
  - Дерево: папки и заметки на кириллице, новая заметка и папка, теги всего хранилища.
  - Редактор CodeMirror 6: Markdown, свойства YAML вверху, подсветка кода в блоках,
    автодополнение `[[` (заметки, затем `#` — заголовки) и `#` (теги), Ctrl+клик по ссылке.
  - Режимы «Редактор / Просмотр / Рядом». Просмотр: формулы KaTeX (`$…$`, `$$…$$`), код на C,
    Python, SQL, JS и MATLAB, задачи-чекбоксы, таблицы; ссылки и теги кликаются, ссылка на
    несуществующую заметку создаёт её (как в Obsidian).
  - Автосохранение через 0,7 с после правки и при закрытии вкладки.
  - Обратные ссылки с контекстом строки; клик открывает заметку на нужной строке.
- Ctrl+O — быстрый переход по названию (можно сразу создать заметку), Ctrl+Shift+F — поиск по
  тексту всех заметок (префиксы слов, кириллица) и по тегам, вложенные теги тоже.
- Удаление — в папку `.trash` хранилища, с подтверждением.
- 184 теста (после этапа 2 было 149): разбор ссылок, тегов, заголовков и свойств, поиск заметки
  по имени как в Obsidian, отрисовка Markdown, фильтр быстрого перехода, API заметок.

**Как проверить**

```bash
npm run dev
```

Открой http://127.0.0.1:5180/notes — слева твоя заметка из OneDrive. Создай вторую заметку, напиши
в ней `[[` и выбери первую — у первой справа появится обратная ссылка. Напиши `$$e^{i\pi}+1=0$$`
и переключись на «Просмотр» — формула отрисуется. Потом открой vault в Obsidian: всё на месте.

**Приёмка (проверено во встроенном браузере на тестовом хранилище)**

- В заметке «Пределы» набрано `[[Произв` → подсказка «Производная (Матанализ)» → Enter: в файле
  `[[Производная]]`, у «Производной» появилась обратная ссылка с контекстом.
- Формула производной и замечательный предел отрисованы KaTeX; код на C, Python и MATLAB подсвечен.
- Файл изменён на диске, пока заметка открыта, — текст обновился сам. Изменён снаружи, когда
  в приложении есть несохранённая правка, — появилось «Заметку изменили снаружи» с выбором,
  на диске ничего не перезаписано до выбора.
- Ctrl+O, Ctrl+Shift+F, создание заметки по ссылке, удаление в `.trash` работают; на ширине
  телефона страница не уезжает вбок, на широком экране — три колонки во всю высоту.
- Твой vault в OneDrive только прочитан (видна 1 заметка), ничего в нём не изменено. База после
  проверки восстановлена из копии.

**Решения**

- Проверки пишут только в тестовое хранилище `vault/` в папке проекта (оно в `.gitignore`), а не в
  твой OneDrive: конспекты — самое ценное, на них не экспериментируем.
- Каждое сохранение несёт «отпечаток» версии, которую ты видел. Если файл за это время изменили в
  Obsidian или OneDrive, приложение не перезаписывает его молча, а спрашивает (риск №1 из ASSESSMENT).
- Сохранение — через временный файл и переименование: Obsidian и OneDrive не увидят полфайла.
- Ссылки ищутся как в Obsidian: по имени без `.md` и без учёта регистра; при одинаковых именах —
  заметка из той же папки, потом ближайшая к корню.
- Редактор, Markdown и формулы загружаются только на странице «Заметки» — остальные экраны не
  стали тяжелее (основной файл даже уменьшился: ~620 КБ вместо ~760 КБ).
- Переименование и перемещение заметок — на этапе 5, вместе с правкой ссылок по всему хранилищу:
  без неё переименование ломало бы ссылки.

**Известное**

- Пока нет: переименования, встраиваний `![[…]]` (показываются ссылкой), вставки картинок,
  палитры команд и графа — это этап 5. Дневные заметки и шаблоны — этап 4.
- Файлы OneDrive «только в облаке» при первом открытии скачиваются — первая индексация большого
  хранилища может занять время.

## Этап 2 — план и «Сегодня» (18.11.2026)

**Сделано**

- Планировщик: общий бюджет на день (по умолчанию 60 мин) делится между 1–2 курсами по очереди
  блоками ~30 мин; длинные лекции режутся на части не короче 10 минут; лекции + практика
  (семинары, разборы задач); приоритеты и сроки курсов (CS50P — к 1 февраля 2027); выходные,
  дни без учёбы, разная нагрузка по дням недели.
- Перепланирование: в первый заход нового дня план пересобирается от того места, докуда
  досмотрено. Невыполненное переезжает вперёд и сдвигает остальное, сделанное остаётся на своих
  днях. Плюс кнопка «Перепланировать».
- Мастер плана `/plan`: курсы, приоритет, срок, начало, минут в день (и отдельно по дням недели),
  предметов в день, учебные дни, дни без учёбы, практика.
- Главная = экран «Сегодня»: баннер со следующей частью плана, «План на сегодня» (карточка
  открывает плеер ровно на своём отрезке), прогресс дня, серия дней подряд, «Мои задачи»
  (добавить, отметить, перенести на завтра, удалить), неделя, «Путь к Computer Vision», «Мои курсы».
- Плеер: часть плана начинается со своего начала, в конце плеер встаёт на паузу и показывает
  «Часть выполнена» с кнопками «Следующая часть» и «Смотреть дальше»; есть «Отметить выполненной».
  Плеер считает реально проигранное время — для серии и строки «в плеере сегодня».
- Календарь `/calendar`: неделя и месяц, листание, «Сегодня», цвет по предмету с легендой; клик по
  дню месяца открывает его неделю.
- Витрина `/dev/ui`: раздел «План и календарь».
- 149 тестов (после 1b было 93): планировщик (17), даты, серия, путь к CV, API плана и задач,
  отрезки плеера, календарь.

**Как проверить**

```bash
npm run dev
```

1. http://127.0.0.1:5180 → «Составить план» → проверь курсы и минуты → «Составить план».
2. На главной — части на сегодня примерно на час, два предмета.
3. Открой часть: плеер начнёт с её начала, в конце остановится и покажет «Часть выполнена».
4. Пропуск дня: открой http://127.0.0.1:5180/?day=2026-11-19 (любой следующий день) — сегодняшние
   части переехали на этот день, остальное сдвинулось (видно в календаре). Без `?day=` план
   вернётся к настоящему сегодня.

**Приёмка (проверено во встроенном браузере)**

- План по умолчанию (5 курсов трека 1, 60 мин, пн–пт, 2 предмета): на «Сегодня» две части по
  30 минут — CS50x и 18.01, всего 1 ч.
- Пропуск дня: открыт четверг 19.11 — обе части среды переехали на четверг, части четверга — на
  пятницу, пятницы — на понедельник 23.11 (выходные пропущены), и так далее по всему плану.
- Часть 0:00–30:00 лекции 18.01: плеер встал ровно на 30:00, часть отмечена, на «Сегодня» —
  30 из 60 минут и «Дальше по плану: CS50x». Вторая часть отмечена кнопкой — «1 день подряд».
- Задачи, «Перепланировать» с подтверждением, календарь (неделя, месяц, листание) работают;
  на ширине телефона страницы не уезжают вбок.
- Проверка шла на твоей базе с резервной копией; после проверки база восстановлена — твой
  прогресс не тронут, плана пока нет: составь свой в мастере.

**Решения**

- Бюджет общий на день, а не «60 минут на курс», как в SPEC: так решили в интервью (BRIEF).
  Поэтому в приёмке «~60 минут», а не «~180».
- План строится от того, докуда досмотрено видео: посмотрел больше или меньше — план подстроится сам.
- Часть, отмеченная вручную, считается просмотренной до конца — иначе план предложил бы те же
  минуты ещё раз.
- Часть, досмотренная раньше своего дня, переезжает на сегодня: в истории видно, когда учился.
- Серия — дни, где было ≥ 5 минут в плеере или выполненная часть.
- Календарь живёт внутри «Главной» (BRIEF): пункт меню «Главная» подсвечен и в календаре, и в мастере.
- Цвета предметов: программирование — фиолетовый, математика — розовый, физика — оранжевый;
  инженерия, робототехника и CV — цвета своих треков.

**Известное**

- Ссылка на дневную заметку на «Сегодня» появится вместе с заметками (этап 3).
- Основной файл приложения ~760 КБ (232 КБ в сжатом виде) — можно разделить по страницам позже.

**Как проверить**

```bash
npm run dev
```

Открой http://127.0.0.1:5180 — главная и разделы меню. Проверка сервера: http://127.0.0.1:5180/api/health.

**Решения**

- TypeScript 6.0, а не 7.0: линтер typescript-eslint пока не поддерживает седьмую версию.
- В режиме разработки интерфейс отдаёт Vite (порт 5180), а API работает на 5181; Vite сам пересылает
  запросы `/api`. В обычном запуске (`npm start`) всё работает в одном процессе на 5180.
- `.env` читается встроенной функцией Node (`process.loadEnvFile`), без пакета dotenv.
- Шрифты (Inter, Unbounded) лежат внутри приложения, а не грузятся из Google Fonts: работают офлайн.
- Классы объединяет пакет `cn` от авторов shadcn вместо `clsx` + `tailwind-merge`.
- Коммиты подписаны скрытым email GitHub (`…@users.noreply.github.com`).

**Известное**

- `npm audit` показывает уязвимости только в инструментах разработки: `picomatch` (через Vite, Vitest,
  typescript-eslint; исправленной версии пока нет) и старый `esbuild` внутри `drizzle-kit`. В само
  приложение они не попадают (`npm audit --omit=dev` — 0 уязвимостей).
