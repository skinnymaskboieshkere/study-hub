## Этап 0 — каркас + GitHub (18.11.2026)

**Сделано**

- Vite 8 + React 19 + React Router 8, Tailwind CSS 4 + shadcn/ui, Fastify 5, SQLite + Drizzle, zod.
- ESLint, Prettier, Vitest; CI в GitHub Actions: типы, линтер, форматирование, тесты, сборка.
- Верхнее меню из пяти разделов, фиолетово-чёрная тема, страницы-заглушки разделов.
- `GET /api/health` → `{"status":"ok"}`: заодно проверяет, что база отвечает.
- Первая миграция базы (таблица `settings`); миграции применяются при старте сервера.
- `CLAUDE.md`, `README.md`, `LICENSE` (MIT), `.env.example`.

**Как проверить**

```bash
npm run dev
```

Открой http://127.0.0.1:5180 — главная и разделы меню. Проверка сервера: http://127.0.0.1:5180/api/health.

**Решения**

- TypeScript 6.0, а не 7.0: линтер typescript-eslint пока не поддерживает седьмую версию.
- В режиме разработки интерфейс отдаёт Vite (порт 5180), а API работает на 5181; Vite сам пересылает
  запросы `/api`. В обычном запуске (`npm start`) всё работает в одном процессе на 5180.
- `.env` читается встроенной функцией Node (`process.loadEnvFile`), без пакета dotenv.
- Шрифты (Inter, Unbounded) лежат внутри приложения, а не грузятся из Google Fonts: работают офлайн.
- Классы объединяет пакет `cn` от авторов shadcn вместо `clsx` + `tailwind-merge`.
- Коммиты подписаны скрытым email GitHub (`…@users.noreply.github.com`).

**Известное**

- `npm audit` показывает уязвимости только в инструментах разработки: `picomatch` (через Vite, Vitest,
  typescript-eslint; исправленной версии пока нет) и старый `esbuild` внутри `drizzle-kit`. В само
  приложение они не попадают (`npm audit --omit=dev` — 0 уязвимостей).
